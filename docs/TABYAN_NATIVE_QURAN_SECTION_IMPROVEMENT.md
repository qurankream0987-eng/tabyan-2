# تقرير تحسين قسم القرآن في Native

## النطاق

هذه المرحلة حسّنت تجربة قسم القرآن في تطبيق Native لتقترب من الموقع، مع استثناء صريح للمصحف وملفات QCF والتسميع داخل المصحف.

## القيود المحفوظة

| القيد | النتيجة |
|---|---|
| `MUSHAF_ASSETS_ENABLED=false` | مؤكد من الكود |
| `QCF_FILES=0` داخل حزمة Native | مؤكد بفحص الملفات |
| ظهور مسار المصحف في Native | غير مضاف |
| استعادة route للمصحف | لم تحدث |
| إضافة تسميع داخل المصحف | لم تحدث |
| Bundle ID أو Expo project ID أو API domain | لم تتغير |
| Production/App Store build أو App Review | لم يبدأ |

## ما تم تنفيذه

### شاشة التقدم

- تعرض السجلات الحقيقية من `student.progress`.
- تعرض اسم المستوى، الحالة، الجلسات المكتملة، الأجزاء المكتملة، ومتوسط التقييم.
- تعرض شريط تقدم محسوبًا من بيانات المستوى المتاحة.
- تتعامل مع حالات التحميل والفشل وعدم وجود بيانات.

ملاحظة: عقد الخادم الحالي يعيد `levelId`, `status`, `completedJuz`, `completedSessions`, `averageScore`, `name`, `path`, و`orderIndex`. لا توجد حقول إجمالي مستهدف للجلسات أو الأجزاء؛ لذلك لا تدّعي الشاشة نسبة منهجية غير موجودة في العقد.

### المستويات ومتطلب العقيدة

- أصبح متطلب العقيدة يفتح مستوى العقيدة المقابل داخل مسارات Native الحالية عند توفر `aqeedahLevelId`.
- لم يتغير منطق البوابة أو الترقية في الخادم.

### اختبار تحديد المستوى

- الحد الأقصى للتسجيل أصبح 300 ثانية مثل الموقع.
- أضيف عرض مرحلي لحالة الاختبار: التعليمات، التسجيل، الرفع، ثم المراجعة أو النتيجة.
- تظهر نتيجة المستوى وملاحظات المراجع من عقد `student.placementStatus`.
- توجد مساحة لدرجات تفصيلية اختيارية فقط إذا أضافها العقد مستقبلًا؛ العقد الحالي لا يعيد درجات تفصيلية.
- لم تتغير طريقة الرفع أو عقد API.

### القراءات والإجازات

- رفع الشهادة يقبل PDF وJPG وJPEG وPNG.
- حد الملف 10MB.
- تحسن مسار المستخدم الذي لم يحصل على إجازة بعد.
- لم تتغير قواعد اعتماد الإجازة أو مصدر البيانات.
