# تدقيق توافق الإدخال العربي الكامل — Tabyan

**التاريخ:** 15 سبتمبر 2026  
**النطاق:** Web، Native Mobile، مكتبة التطبيع المشتركة، وعقود tRPC/backend  
**الحالة:** مكتمل ضمن نطاق الإدخال فقط

## 1. حدود العمل

تم تنفيذ التدقيق والإصلاحات دون:

- بدء Build 6 أو تغيير إعدادات توقيع iOS.
- إعادة تصميم الشاشات.
- تغيير قواعد العمل غير المتعلقة بالإدخال.
- تغيير تدفق المصادقة.
- استعادة QCF أو تعديل منطق الفيديو.
- إضافة ميزات جديدة.

الهدف كان جعل إدخال الأسماء العربية، الأرقام العربية-الهندية والفارسية، الهواتف، OTP، الحقول الرقمية، البحث، والنصوص الطويلة متسقًا بين Web وNative والخادم.

## 2. العقد المشترك

الأداة المشتركة في `lib/tabyan-trpc/src/lib/input-normalization.ts` هي مصدر الحقيقة للتحويلات التالية:

| الوظيفة | السلوك |
|---|---|
| `normalizeDigits` | تحويل `٠١٢٣٤٥٦٧٨٩` و`۰۱۲۳۴۵۶۷۸۹` إلى ASCII فقط، مع إبقاء بقية النص كما هو |
| `normalizePhoneInput` | تطبيع الأرقام والمسافات والفواصل والأقواس وتحويل بادئة `00` إلى `+` |
| `normalizePersonName` | إزالة المسافات الطرفية ودمج المسافات المتتابعة |
| `isValidPersonName` | طول 3–50، وجود حرف Unicode واحد على الأقل، ورفض محارف التحكم/التنسيق والقيم غير الاسمية |

لم تُستخدم أداة تحويل الأرقام للعرض (`toArabicDigits`) لتغيير قيمة إدخال المستخدم.

## 3. جرد الحقول

تم العد من ملفات المصدر الحالية:

- Web: **102** `input`، **21** `textarea`، **36** `select`، أي **159** عنصر JSX خام.
- Native: **42** افتتاحية `TextInput` مباشرة في ملفات التطبيق والمكونات. بعض السطور تحتوي أكثر من `TextInput` في JSX مضغوط، لذلك لا يمثل عد الأسطر عدد الحقول.

الحقول التقنية المقصودة بقيت ASCII-only:

- usernames التقنية.
- مفاتيح المواد الشرعية.
- `startVerseKey`.
- صيغة وقت الجدول `HH:MM`.
- regex لمسارات التخزين وروابط YouTube.

هذه ليست حقول أسماء أو نصوص عربية، ولم يتم توسيع قبولها حتى لا تتغير عقود النظام.

## 4. الإصلاحات المنفذة

### Web

- `PhoneField`: تطبيع الأرقام العربية والفارسية قبل إزالة المحارف غير الرقمية، مع عدم اعتبار الأرقام الشرقية محارف غير صالحة.
- `OtpInput`: تطبيع الإدخال الفردي واللصق قبل التحقق والتحرك بين الخانات.
- `MushafIndexSheet`: قبول أرقام الصفحات العربية والفارسية.
- `MushafSearchSheet`: إزالة نسخة التطبيع المحلية العربية فقط واستعمال الأداة المشتركة، وبالتالي دعم العربية-الهندية والفارسية معًا.
- `RecitationSetupSheet` و`RecitationFlow`: تحويل حقول الآيات إلى نص ذي `inputMode="numeric"`، وتطبيع الأرقام مع حراسة الحالة الفارغة قبل التحويل إلى رقم.
- صفحات الإدارة: تطبيع أرقام آية اليوم، ترتيب المواد، إعدادات المستويات، الجداول، الاختبارات، وساعات حظر المستخدمين.
- تم تغيير الحقول الرقمية التي كانت `type="number"` في نطاق الإصلاح إلى نص رقمي حتى لا يرفض متصفح Web الأرقام الشرقية قبل وصولها إلى handler.

### Native Mobile

- `AdminInput`: التطبيع يحدث فقط عند `keyboardType="number-pad"`.
- الحقول النصية العامة، بما فيها كلمات المرور والملاحظات، تمرر القيمة كما كتبها المستخدم byte-for-byte.
- بقيت حقول usernames وكلمات المرور التقنية دون تطبيع أو تحويل تلقائي.

### Backend والاختبارات المشتركة

لم تتغير قواعد التحقق أو قواعد العمل في الخادم. تمت إعادة استخدام العقد الموجود بدل إضافة قواعد متوازية في الواجهات، مع إبقاء التحقق النهائي في الخادم.

## 6. نتائج التدقيق النهائية

- الأرقام العربية والهندية والفارسية مدعومة في مسارات الإدخال الرقمي التي كانت تفشل سابقًا.
- الهاتف وOTP والبحث في المصحف لا يعتمدون على `/\D/` قبل التطبيع.
- كلمات المرور لا تمر عبر تطبيع الأرقام في Native.
- النصوص الطويلة والأسئلة والملاحظات لا تخضع لفلترة رقمية.
- الأسماء العربية لا تُعامل كـ ASCII-only.
- الحقول التقنية ASCII-only موثقة ومقصودة.
- لم تُثبت مشكلة API جديدة ضمن هذا التدقيق؛ بقي التحقق النهائي server-side.

## 7. ما لم يُنفذ

لم يتم اعتبار اختبار لوحة مفاتيح فعلية على جهاز iPhone أو Android بديلًا عن اختبارات TypeScript/export. يلزم اختبار يدوي على جهاز فعلي قبل الإصدار للتحقق من سلوك لوحة المفاتيح العربية/الفارسية، اللصق، واتجاه المؤشر في الحالات الأصلية الخاصة بالنظام. هذا خارج الإصلاح البرمجي الحالي ولا يتطلب بدء Build 6.
