# Wave 2 Quran-Specialized ASR Checkpoint Benchmark

**Research date:** 2026-10-11  
**Depth:** Quick  
**Sources consulted:** 10  
**Status:** Candidate feasibility review only; no candidate inference was completed.

## Executive summary

The strongest Quran-specific candidates found have promising publisher-reported results, but none has a valid matched score against Tabyan’s Tarteel Whisper Base baseline. The available claims come from different test sets, scoring procedures, and model types. Quran-Lab’s published benchmark is useful context, but its scores are not measurements on the public Al-Mulk 67:1–3 Alafasy clip used by Tabyan. [[5]](https://huggingface.co/datasets/Quran-Lab/quranic-asr-benchmark) No candidate should be called more accurate for Tabyan until it is run on that exact audio under the same scoring rules.

WasimLHR’s Whisper Quran v1 is a large, non-streaming Whisper Large-v3 fine-tune. Its author reports 5.74% WER for the released checkpoint and 5.35% for a prior best checkpoint on 115 examples; the card declares noncommercial terms and lists Alafasy among its training tracks. [[1]](https://huggingface.co/wasimlhr/whisper-quran-v1) [[3]](https://huggingface.co/datasets/Buraaq/quran-md-ayahs) The 6.17 GB upstream weights exceed this workspace’s available memory. [[2]](https://huggingface.co/wasimlhr/whisper-quran-v1/tree/main) FastConformer is a more practical research target by size and has a separate cache-aware streaming model, but the repositories declare no-profit terms and file access is gated. [[6]](https://huggingface.co/Muno459/fastconformer-quran) [[7]](https://huggingface.co/Muno459/fastconformer-quran-streaming) Zipformer is a streaming phoneme recognizer, not an ordinary Arabic-text transcriber. [[8]](https://huggingface.co/Quran-Lab/zipformer_p-arabic-v3) DeepDML’s smaller Whisper Base model declares Apache-2.0 and reports WER, but its evaluation description is too incomplete to compare. [[9]](https://huggingface.co/deepdml/whisper-base-ar-quran-mix-norm) [[10]](https://huggingface.co/api/models/deepdml/whisper-base-ar-quran-mix-norm)

The existing baseline report was corrected: 23.7% is Tabyan-normalized Quran WER (Q-WER), not “Raw-text WER.” The orthography-sensitive score on the same transcript is 57.9%. No candidate accuracy, alignment, false-positive, latency, memory, or chunk/context-carry result was measured in this pass.

## Scope and method

This was research and execution-feasibility work only. The intended matched input remains the same public Al-Mulk 67:1–3 Alafasy audio. No student audio was used; no model weights were downloaded or run; no application, provider, database, Python configuration, or deployment was changed; and no paid GPU was provisioned. Published scores below are labeled as author/benchmark claims, not Tabyan measurements.

## Baseline metric audit

The prior comparison table listed `9/38` errors and `23.7%` as “Raw-text WER.” That label was wrong: the scoring path applies Tabyan’s `normalizeQuranText` before token comparison. The existing report now calls this **Tabyan-normalized Quran WER (Q-WER)**. On the same 38-word reference and saved baseline hypothesis, the letter-form-preserving comparison is **22/38 = 57.9%**. See the corrected [provider comparison](../docs/TABYAN_RECITATION_PROVIDER_LIVE_COMPARISON.md) and the [normalizer implementation](../artifacts/tabyan/src/lib/recitation-ai/normalizer.ts).

Q-WER first applies NFC, maps dagger alif to alif, removes Quranic marks, tatweel and format characters, folds ٱ/أ/إ/آ to ا, and folds ى to ي. It preserves hamza on waw/ya and taa marbuta. [[Local implementation]](../artifacts/tabyan/src/lib/recitation-ai/normalizer.ts) The orthography-sensitive comparison does not apply those letter-form folds. These two metrics answer different questions; neither should be labeled simply “raw” without documenting its tokenization and normalization. The baseline’s 37/38 first-try matcher result is a separate alignment summary, not word-level WER.

## Feasibility and benchmark status

The workspace check showed 4 CPU cores, about 7.8 GiB total RAM, about 5.2 GiB available memory, no swap, and no GPU. The Wasim checkpoint’s 6.17 GB of shard files is larger than available memory before model/runtime overhead, so an upstream CPU load was not feasible. The Muno FastConformer streaming and Zipformer file requests returned HTTP 401 because those repositories are gated. DeepDML is smaller, but the workspace lacks PyTorch and Transformers; I did not install packages or edit Python configuration. Prior managed package-resolution failures make an unsupported direct install inappropriate here.

No candidate was inferred. Therefore the following remain **unmeasured**: WER/PER on the Tabyan sample, alignment accuracy, false-positive behavior, latency, peak memory, 2/5/10/15/30-second chunking, and cross-chunk context carry. The author-published Wasim ONNX derivative was not run; it is not a substitute for an upstream result.

## Recommendation

Do not rank, switch, or promote any candidate on the evidence gathered here. If a next test is authorized, first resolve access and license conditions for the gated FastConformer checkpoints; the offline model is the clearest full-text candidate among the reported small models, while its separate streaming model needs its published result discrepancy explained. [[6]](https://huggingface.co/Muno459/fastconformer-quran) [[7]](https://huggingface.co/Muno459/fastconformer-quran-streaming) DeepDML is a possible CPU-feasibility check after a supported managed runtime is available, but its self-reported score is not independently comparable. [[9]](https://huggingface.co/deepdml/whisper-base-ar-quran-mix-norm) Treat Zipformer as a separate phoneme-recognition experiment. [[8]](https://huggingface.co/Quran-Lab/zipformer_p-arabic-v3) For Wasim, obtain written permission for any commercial use and verify training-audio rights and possible Alafasy overlap before considering further testing. [[1]](https://huggingface.co/wasimlhr/whisper-quran-v1) [[3]](https://huggingface.co/datasets/Buraaq/quran-md-ayahs)

## Limitations

All ten web sources are Tier 3 primary model/dataset pages. They are evidence of what the publishers declare, not independent accuracy or rights validation. No external model was loaded, and no user/student recording or gated benchmark audio was accessed. The exact Alafasy recording overlap, each model’s score on Tabyan’s sample, and all requested chunk/context measurements remain unknown.
