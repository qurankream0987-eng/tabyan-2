# TABYAN Smart Mushaf — Component License and Rights Matrix

**Snapshot date:** 2026-10-15  
**Purpose:** Separate code permissions from model, data, font, and recording rights.  
**Decision:** **`READY_RENDERER_RIGHTS_UNKNOWN`.** The pinned package code is MIT-licensed; exact rights for the critical QPC/QUL/KFGQPC resources remain unestablished. The full feature stack is not cleared for commercial distribution.

Citation numbers use the shared source registry in the ecosystem audit. This is a technical rights review, not legal advice.

## Executive conclusion

The repository-level MIT license covers code, not the QPC V4 text/glyph data, layout, fonts, or other external assets. The immutable source pin inspected for this rights report is [`230b4b7218d1fc56e51e7f165830c15e9ce4efe2`](https://github.com/alheekmahlib/quran_library/tree/230b4b7218d1fc56e51e7f165830c15e9ce4efe2); its `pubspec.yaml` reports version 5.0.2. Its `NOTICE` says QCF/QUL/KFGQPC assets are governed separately. QUL's official resource index says resources are intended to be packaged, while its FAQ directs users to dataset-specific terms. That combination does not establish all rights for the exact bundled files. [[7]](https://raw.githubusercontent.com/alheekmahlib/quran_library/230b4b7218d1fc56e51e7f165830c15e9ce4efe2/LICENSE) [[8]](https://raw.githubusercontent.com/alheekmahlib/quran_library/230b4b7218d1fc56e51e7f165830c15e9ce4efe2/NOTICE) [[46]](https://qul.tarteel.ai/resources) [[47]](https://qul.tarteel.ai/docs/faq)

The largest known commercial restriction is Quran-Lab NPL-1.2. It prohibits charging for the Work or any feature it powers, including a paid subscription, paywall, trial that later requires payment, or advertising revenue on that feature. It permits Local Use and limited free or strictly documented direct-cost-recovery hosting, but requires derivatives to remain under the same NPL terms. A Zipformer-backed paid Tabyan feature is therefore blocked under the license text reviewed here unless the model is replaced or the rights are otherwise resolved through legal review. [[14]](https://raw.githubusercontent.com/alheekmahlib/quran_library/main/assets/quran_lab/LICENSE-QuranLab-NPL-1.2.txt) [[31]](https://huggingface.co/Quran-Lab/zipformer_p-arabic-v3/blob/main/README.md)

QUL/KFGQPC asset rights, exact Quran text/data provenance, and each audio recording’s terms remain unknown. The entire Smart Mushaf cannot be marked commercially clear. Do not bundle, cache offline, modify, or redistribute those assets based solely on MIT code or public download access.

## Exact renderer resource status

The detailed field-by-field inventory is in [`TABYAN_SMART_MUSHAF_AUTHORITATIVE_RIGHTS.md`](TABYAN_SMART_MUSHAF_AUTHORITATIVE_RIGHTS.md). The critical package resources are bundled rather than fetched at renderer runtime: QPC V4 glyph/text data, word-by-word data, page/word-position data, and QFC4 page fonts. Separate surah-name, basmala, ayah-number, and Unicode Hafs fonts are also bundled. None of those asset groups is cleared by the package MIT license.

QUL's general statement that resources are intended to be packaged is not ignored, but it does not settle dataset-specific rights, upstream ownership, exact-file identity, or all requested distribution modes. The maintainer-authored no-distracting-ads summary in `quran_library/NOTICE` was not found in the inspected QUL resource records and is not treated as an authoritative license term.

## Renderer substitution check

The pinned `quran_library` reader has a concrete QPC V4 renderer and local asset store. Tasmee word-state rendering is coupled to `QpcV4WordSegment` and `QuranCtrl`/`AyahModel`; no generic renderer plug-in interface was found. A different renderer would require an adapter and UI/state rewiring, so a clean, no-rebuild substitution is **not established**.

The closest alternative found, [quran-ws/quran-engine](https://quran.ws/docs/reference/quran-engine/), has cross-platform word hit-testing, masking, and highlighting, but its engine is not published as a package, its page-data release is Beta, and it has no integrated live-recitation/Tasmee controller. Its page data also derives from KFGQPC and remains under upstream terms. It is not a cleared, ready replacement.

## Required clearance packet before shipping

For each asset, record the provider/rightsholder, exact resource name and version, source URL, checksum, license/permission text, commercial and territory scope, attribution, modification permission, offline cache duration, redistribution permission, and any takedown or sync condition. For each model component, record the exact weight and data hashes, the license file shipped with it, whether the model is hosted or local, whether the feature is free, and whether any output or derivative is redistributed.

Do not use an “MIT” field at repository level to stand in for this packet. Keep the current Tabyan QCF v2 data isolated from candidate QPC V4 resources, and preserve the old reader unchanged until this review and a later acceptance gate both pass.

## Limitations

No formal legal opinion was obtained. QUL resource pages and its FAQ were inspected, but no resource-specific license for the exact bundled files was found. KFGQPC's official pages could not be fetched. The model weights were not downloaded, so no file hash or package-level license manifest was validated. Provider recording terms were not reviewed one reciter at a time.
