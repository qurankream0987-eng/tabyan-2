# توصية مزوّد التعرّف الآني على التلاوة القرآنية لتبيان

**تاريخ البحث:** 5 أكتوبر 2026  
**النطاق:** بحث وتوصية فقط؛ لم يتغير مزوّد التطبيق أو الكود أو قاعدة البيانات أو النشر.

فسّرت طلب «مزوّد ترتيل» على أنه مزوّد ASR للتلاوة القرآنية الحي، بما في ذلك التحقق من وجود API رسمية من Tarteel.

## الخلاصة

لم أتحقق من وجود API عامة مستضافة من Tarteel لتعرّف التلاوة القرآنية الحي. مقال مركز المساعدة الرسمي بتاريخ 27 سبتمبر 2025 يقول إن API عامة للمطورين غير متاحة، ويشير إلى QUL لموارد القرآن القابلة للتنزيل [R01]. توثيق MCP المنفصل يصف أدوات للاستعلام عن محتوى القرآن، ولا يصف إرسال الصوت أو إرجاع تفريغ آني [R02]. قد توجد خدمة خاصة أو عرض أحدث لم يظهر في المصادر العامة؛ يلزم سؤال Tarteel مباشرة قبل اعتبار ذلك حسمًا نهائيًا.

**التوصية العملية:** لا تبدّلوا المسار الحالي ولا تعتمدوا مزوّدًا جديدًا للإنتاج بناءً على دعم العربية وحده. أبقوا مسار OpenAI الموجود في التطبيق كخط مقارنة/احتياط، واختبروا نموذج Tarteel `whisper-base-ar-quran` على نقطة GPU خاصة بوصفه المرشح القرآني المتخصص. النموذج أوزان قابلة للتنزيل وليست خدمة بث مستضافة جاهزة؛ ولم يظهر ضمن مزوّدي Hugging Face للاستدلال عند فحص الصفحة [R03–R04]. يلزم غلاف للبث حول النموذج، مع تحقق منفصل من حقوق بيانات التدريب والأوزان المحوّلة قبل أي استخدام تجاري.

للمقارنة مع خدمة عامة غير متخصصة بالقرآن، Google Cloud Speech-to-Text V2 / Chirp 3 هو المرشح الأوضح في الوثائق التي راجعتها: توثيق Google يذكر البث عبر `StreamingRecognize`، وجدول اللغات يسرد `ar-SA` لـChirp 3 في منطقتي EU وUS. لكن هذا لا يثبت جودة تلاوة القرآن ولا يعني أن الصوت يعالج داخل السعودية [R07–R09].

## ما تدعمه الأدلة

| الخيار | ما تؤكده الوثائق | ما لا تثبته | التقييم لتبيان |
|---|---|---|---|
| **Tarteel API الرسمية** | مقال Tarteel يقول إنه لا يوفّر API عامة؛ MCP يتيح استعلام أدوات ومحتوى قرآني [R01–R02]. | لا يستبعد ذلك API خاصة، أو شراكة، أو إطلاقًا بعد تاريخ المقال. | لا تعتمدوا على وجود خدمة ASR مستضافة قبل تأكيد مكتوب من Tarteel. |
| **Tarteel `whisper-base-ar-quran`** | بطاقة النموذج تصفه بأنه Whisper Base مضبوط للقرآن، وتعرض WER قدره 5.7544. مستودع النموذج يعلن Apache-2.0 [R03–R04]. | بطاقة النموذج لا تعرّف مجموعة التقييم أو بيانات التدريب بما يكفي لمقارنة عادلة؛ WER المعلن وحده لا يثبت دقة الطلاب أو الكمون. ولم توثّق واجهة بث مستضافة. | أفضل مرشح قرآني لتجربة خاصة، لا مزوّد جاهز للإنتاج. يجب بناء غلاف بث/تقطيع والتحقق من سلسلة الحقوق. |
| **OpenAI Realtime** | توثيق OpenAI يشرح `gpt-live-transcribe`، وإرسال deltas جزئية ثم نتيجة نهائية عند اعتماد المقطع [R05]. | لم تثبت الوثائق التي راجعتها جودة قرآنية أو تعرّفًا على التجويد/القراءات. لا أستنتج دقة `ar-SA` أو دقة القرآن من كون الجلسة آنية. | التطبيق يحتوي مسار OpenAI فعليًا، لكن واجهة المشروع ما زالت تصف حالة المزوّد بأنها «قيد التقييم — لم يُعتمد». الاختبار الداخلي السابق رجّح هذا المسار على تحويل محلي لـTarteel في اختبار اصطناعي لمقرئ واحد فقط؛ لا يكفي ذلك لاعتماده العام. |
| **Google Cloud STT V2 / Chirp 3** | توثيق V2 يذكر البث، وتظهر `ar-SA` في جدول اللغات مع اختلاف المنطقة حسب النموذج؛ Chirp 3 مدرج في EU وUS، بينما تختلف مناطق `long` و`short` [R07–R09]. | دعم العربية العامة لا يثبت مطابقة ألفاظ القرآن أو دقة مواضع الكلمات، كما أن المناطق الموثقة لا تعني استضافة داخل السعودية. | مرشح مناسب لاختبار مقارنة عام، وليس توصية قرآنية مستقلة. تحقّقوا من النموذج والمنطقة الفعليين قبل الدمج. |
| **Speechmatics Realtime** | توثيق الخرج يذكر partials أولية عادةً في أقل من 500ms، ثم finals أعلى دقة وفق وصف المزوّد [R10]. | صفحة الخرج التي راجعتها لا تثبت رمز لغة عربية محددًا في Realtime، ولا توجد فيها نتيجة قرآنية مستقلة. | لا أضعه قبل Google كمرشح عربي حيّ حتى يُثبت المسار/اللغة باختبار preflight. يوجد في سجل المشروع رفض سابق لإعداد بروتوكولي معيّن؛ لا تستخدموا ذلك الإعداد دون تصحيحه والتحقق منه. |
| **Azure Speech** | جدول Microsoft يسرد `ar-SA` لبعض الوظائف، ودليل SDK يشرح أحداث التعرف الوسيطة والنهائية [R11–R12]. | الجدول لا يثبت وحده أن وضع التعرف الحي المحدد المطلوب متاح لـ`ar-SA` في المنطقة المقصودة. | بديل ثانوي، بعد تأكيد وضع البث والمنطقة مع اختبار فعلي. |

## التراخيص والنماذج القرآنية الأخرى

- بطاقة `wasimlhr/whisper-quran-v1` تسمح بالاستخدام الشخصي والتعليمي وغير التجاري، وتشترط إذنًا كتابيًا للاستخدام التجاري. ما يذكره صاحب البطاقة عن نظام آني يعتمد على مقاطع Whisper بطول يقارب 10 ثوانٍ؛ هذا ليس API مستضافة ولا دليلًا على بث أصلي منخفض الكمون [R13].
- بطاقة نموذج Tadabur ومستودع بياناته يعلنان CC BY-NC 4.0؛ لذلك لا أوصي بهما لتشغيل تجاري افتراضيًا من دون إذن مناسب [R14–R15]. رخصة ورقة arXiv تخص الورقة نفسها ولا تمنح تلقائيًا حقوق الأوزان أو التسجيلات [R16].
- إعلان Apache-2.0 في مستودع Tarteel يخص ما يعلنه المستودع؛ لا يحسم وحده حقوق التسجيلات المستخدمة في التدريب أو حقوق نسخة محوّلة/مكمّمة بعينها.
- نتائج WER المنشورة ليست قابلة للمقارنة المباشرة بين هذه النماذج لأن مجموعات الاختبار والبروتوكولات مختلفة أو غير موضحة.

## قرار مقترح وبوابات التقييم

1. **حاليًا:** لا تغيير في توجيه الصوت. استخدموا مسار OpenAI الموجود كخط أساس داخلي فقط، لا كاعتماد نهائي للمزوّد.
2. **مرشح متخصص:** تجربة Tarteel على نقطة خاصة لا تصل إليها بيانات الطلاب، مع تقطيع متداخل قصير ثم مطابقة البادئة/الكلمات. لا تعتبروا الغلاف المتقطع مساويًا للبث الأصلي، ولا تنقلوا بيانات طلاب إلى التجربة.
3. **مقارنة سحابية اختيارية:** اختبروا Google V2 على النموذج والمنطقة اللذين يذكرهما جدول `ar-SA` صراحةً. لا تخلطوا اختبار اللهجة/اللغة مع اختبار صحة النص القرآني.
4. **بوابة جودة قبل أي اعتماد:** تسجيلات مسموح بها من ثلاثة قرّاء مختلفين على الأقل، تشمل أنماط تلاوة وظروف أجهزة وشبكات متنوعة؛ مقارنة موحّدة لـWER المحافظ وتغطية الكلمات ومواضعها وP50/P95 للـpartials والنتائج النهائية والانجراف في المقاطع الطويلة.
5. **بوابة حقوق وتشغيل:** إثبات ترخيص الأوزان الدقيقة ومصدر البيانات، وقياس تكلفة GPU/الخدمة والتوافر والاحتفاظ بالصوت والمنطقة قبل اختيار الإنتاج.

## حدود البحث

لم أتحقق من سعر الخطة التجارية أو مدد الاحتفاظ أو موقع معالجة البيانات لأي مزوّد؛ تختلف هذه بحسب العقد والمنطقة. كما لم يظهر في المصادر معيار مستقل موحّد يقارن هذه الخيارات على تلاوات قرآنية مماثلة. لذلك التوصية هنا هي اختيار مرشح للتقييم، لا ادعاء أن مزوّدًا اجتاز بوابة إنتاج تبيان.
