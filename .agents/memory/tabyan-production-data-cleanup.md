name: Tabyan production data cleanup
description: Production reset audit constraints, account classification limits, and onboarding persistence behavior.
---

تنظيف Production في تبيان يبدأ دائماً بتقرير قراءة فقط؛ لا يجوز اعتبار الحساب آمناً للحذف اعتماداً على رقم يشبه بيانات الاختبار أو على `account_origin` وحده، لأن الحقل غير مكتمل وقد تتداخل حسابات الاختبار مع حسابات Bootstrap، مع وجود سجلات تابعة للمستخدمين.

**Why:** بيانات Production قد تحتوي حسابات seed/fixture مع مستخدمين حقيقيين، وحذف المستخدم قد يمتد إلى جلسات وتقدم وإشعارات وفتاوى وبيانات أخرى عبر العلاقات.

**How to apply:** اعرض إجمالي الحسابات والتبعيات، صنّف المعروف والمجهول، اعتبر الآمن للحذف صفراً عند وجود شك، وخذ backup وتأكيداً صريحاً قبل أي mutation. حالة الترحيب الحالية محلية في Web وليست محفوظة خادمياً، وMobile لا يملك تدفق onboarding مكافئاً بعد.

قيد بيئي مهم: الاتصال المباشر عبر `DATABASE_URL` قد لا يكون نفس نسخة Production التي تدعم قراءات Production؛ يجب مقارنة عدد المستخدمين ومعرّفاتهم قبل أي كتابة، وعدم تنفيذ الحذف إذا اختلفت النسختان.

**Why:** ظهر اختلاف فعلي بين اتصال مباشر يحوي 40 مستخدماً ونسخة Production للقراءة تحوي 41 مستخدماً، ما يجعل الكتابة على الاتصال المباشر غير آمنة حتى لو كانت البيئة موسومة production.

**How to apply:** استخدم اتصالاً كتابياً موثقاً لنفس نسخة Production مع backup منها، ولا تعتمد على اسم البيئة أو وجود `DATABASE_URL` وحده لإثبات أن الهدف هو Production.
